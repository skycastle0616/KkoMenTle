# 꼬맨틀 알리미

[꼬맨틀](https://semantle-ko.newsjel.ly)은 [Semantle](https://gitlab.com/novalis_dt/semantle)의
한국어판이다. 정답과의 임베딩 유사도만으로 진행하는 구조라, 임베딩이 그 단어를 잘못 읽는 날은
문제 자체가 성립하지 않는다.

꼬맨틀은 날에 따라 문제 자체가 망가진다. 정답으로 삼기엔 무리한 단어이거나, 유사도 점수가
정답의 실제 뜻과 어긋나서 아무리 잘 추측해도 도달할 수 없는 날이 있다.

**이 페이지는 그날 문제가 풀 만한지 판별해서 크게 알려준다.** 힌트는 곁들이는 기능이다.

> 답을 찾아가는 과정이 오래 걸리는 건 난이도이고 그 자체가 게임의 재미다.
> 걸러내야 하는 건 결함이 있는 날이다.

공개 URL — <https://skycastle0616.github.io/KkoMenTle/>

## 판별 로직

축이 셋이다.

| 축 | 재는 것 | 산출 |
|---|---|---|
| `q_reach` | **탐색하다 이 단어를 치게 되는가** | LLM `probe` |
| `q_path` | **가까이 갔을 때 점수가 말을 해주는가** | LLM `probe_words` + 실제 순위 조회 |
| `q_match` | 유사도가 정답의 뜻을 따라가는가 | `matched_ranks` + 1위 단어 점수 |
| `q_word` | 정답으로 내걸기에 공정한 단어인가 | LLM `fairness` |

```
q_match  = 0.80 * Σ(1/순위)/H(16) + 0.20 * norm(first_score, 38, 62)
q_path   = mean(1 - log10(탐색어 순위)/3)        1000위 밖이면 0
base     = 0.20 * q_match + 0.80 * q_reach
path_cap = 0.20 + 0.80 * min(1, q_path / 0.45)
playable = 100 * min(base, q_word, path_cap)

q_match < 0.15  →  점수와 무관하게 🔴   (임베딩 붕괴 게이트)
```

### 왜 q_reach 가 주축인가 — 실측으로 맞췄다

11회차의 **실제 시도 횟수**를 받아 검증했다. q_match 중심이던 옛 식은 시도 횟수와
스피어만 **+0.47**. 부호가 반대다 — 점수가 높을수록 오래 걸렸다.

| | 전체 11 | 힌트 없이 본인이 푼 6 |
|---|---|---|
| 옛 `playable` | **+0.473** | **+0.486** |
| `probe` 단독 | −0.800 | −0.886 |
| 새 `playable` | **−0.764** | **−0.886** |

배합은 격자 탐색으로 골랐다. `q_match` 를 더 실으면 상관이 급격히 나빠진다
(0.2 → −0.71, 0.5 → −0.39, 1.0 → +0.47).

`probe` 는 "이 단어를 아는가"가 아니라 **"정답을 모르는 채 찍어보다가 이걸 치게
되는가"** 다. 뜻이 아무리 쉬워도 탐색 경로에 없으면 낮다. 사람은 상위 50개 이웃을
다 찾아내지 못하고, 상위 10개를 하나도 못 밟은 채 답에 닿기도 한다. 그래서 상위권
목록이 얼마나 깔끔한지보다 **정답 자체가 떠오를 계기가 있는지**가 체감을 지배한다.

확인해야 한다.

### q_path — 바깥에서 안으로 들어오는 길

`q_reach` 와 `q_match` 는 둘 다 **정답에서 바깥을 본다**. 정답을 칠 만한가, 정답 근처에
뭐가 있는가. 그런데 사람은 **바깥에서 안으로** 들어온다.

`들리다`(1625) 가 그 구멍을 드러냈다. 흔한 말이라 `q_reach` 0.6~0.8, 상위권에 소리
관련어도 있어 `q_match` 0.46~0.60 — 두 축 다 통과해서 **73 🟢** 이 떴다. 실제로는
**500~600회 + 힌트**였다.

이유는 없는 쪽에 있었다.

```
소리 · 귀 · 청각 · 목소리 · 소음 · 시끄럽다   →  전부 1000위 밖
듣다 29위(41.43)   울리다 564위   들다 208위
```

`들리다` 는 국어 문법에서 피동의 대표 예시(`듣다 → 들리다`)라 교과서·사전·맞춤법
문서에 눌러앉아 있다. 그 결과 상위권이 문법 용어로 채워졌다 — `목구멍소리`(1위) ·
`종결형`(7) · `의성어`(15) · `관형어`(16) · `예사소리`(17). **맨 자모 20개까지 들어왔다**
(`ㄸ` 59위, `ㅚ` 97위). 어제 `담당하다` 0개, 내일 `공사` 0개인데 이 날만 그렇다.

그 자모들이 진짜 의미 이웃을 1000위 밖으로 밀어냈다. 경로는 맞는데 점수가 침묵한다.

그래서 LLM 에게 **"이 정답을 찾는 사람이 자연스럽게 쳐볼 단어 8개"**(`probe_words`)를
받아, 그 단어들이 실제 1000개 목록 몇 위인지 **결정론적으로 조회**한다. LLM 은 무엇을
쳐볼지만 고르고, 순위는 계산이다.

| | 탐색어 순위 | `q_path` | 점수 |
|---|---|---|---|
| 공사 | 건설1 시공5 건축10 작업22 건물32 도로37 수리282 개발325 | 0.538 | 83 🟢 |
| 들리다 | 듣다29 들다208 올리다718 · 나머지 5개 밖 | 0.098 | **38** 🟠 |

나쁠 때만 물도록 **캡**으로 쓴다. `q_path` 가 `PATH_GOOD`(0.45) 이상이면 캡이 1.0 이라
아예 안 문다. 포화점이 없으면 매일 캡이 물어서 점수를 통째로 끌어내린다 — 실제로
`공사`(경로 8/8 양호)가 부제까지 "점수가 말을 안 해주는 날"로 나왔다.

> 계획서에서 "프로브 방식은 도달 속도를 재는 거라 범위 밖"이라고 빼뒀던 그 방식이다.
> 도달 속도가 아니라 **피드백이 오는가**를 재는 용도로는 이게 맞는 도구였다.

### 임베딩 붕괴는 난이도와 별개다

`속이다`는 멀쩡한 표준어이고 `probe` 도 0.4 로 나쁘지 않다. 하지만 FastText 가
`속(屬, 생물 분류) + 이다`로 쪼개 읽어서 유사어가 전부 생물 분류 용어다. 아무리
잘 찍어도 도달할 수가 없다.

이건 "오래 걸린다"가 아니라 "안 된다"라서 난이도 배합에 섞으면 안 된다. `q_match` 가
`BROKEN_GATE`(0.15) 밑이면 점수와 무관하게 🔴 로 못 박는다.

`q_word`(fairness)는 `min()` 으로 캡을 씌운다. 방언·고어·비표준 표기처럼 정답으로
내거는 것 자체가 부당한 날은 아무리 닿기 쉬워도 그 위로 못 올라간다.

### 순위 가중 · 어간 자기반향

`matched_ranks` 는 개수가 아니라 **통하는 단어의 순위 번호 목록**이다. 1위 이웃은
16위 이웃보다 압도적으로 정보가 많다. 같은 7개라도 자리가 다르면 갈린다.

| 통하는 순위 | 개수비 | 순위가중 |
|---|---|---|
| 1·2·5·6·7·14·16 | 7/16 | 0.634 |
| 10~16 | 7/16 | 0.216 |

정답 어간을 그대로 품은 이웃은 **가장 높은 순위 하나만 남긴다**. `가득히` 날의 상위
16 에 `한가득·가득·가득가득` 이 있었는데, 셋이 높게 뜨는 건 FastText 가 부분 문자열을
보기 때문이지 임베딩이 뜻을 따라간다는 증거가 아니다.

### 등급과 부제

| 점수 | 배지 | 헤드라인 |
|---|---|---|
| 60+ | 🟢 | 오늘은 할 만합니다 |
| 42~59 | 🟡 | 조금 까다롭습니다 |
| 28~41 | 🟠 | 각오하고 들어가세요 |
| ~27 | 🔴 | 오늘은 건너뛰세요 |

임계값도 실측에 맞췄다. 배합이 `q_reach` 중심이 되면서 점수 분포가 통째로 내려왔다.

부제는 어느 축이 묶었는지로 갈린다.

| 조건 | 부제 |
|---|---|
| 붕괴 게이트 | 유사도가 정답의 뜻을 배신하는 날입니다 |
| `q_word` 가 캡 | 정답으로 내걸기엔 공정하지 않은 단어입니다 |
| `q_path` 가 캡 | 가까이 가도 점수가 말을 안 해주는 날입니다 |
| 🟢 `reach` | 탐색하다 보면 자연스럽게 닿는 단어입니다 |
| 🟡 `reach` | 떠올리기까지 좀 헤맬 단어입니다 |
| 🟠 `reach` | 탐색 경로에서 한참 벗어나 있는 단어입니다 |
| 🔴 `reach` | 탐색하다 떠올릴 계기가 거의 없는 단어입니다 |

**판정 영역에는 LLM 자유 문장을 쓰지 않는다.** 처음엔 🟢 인 날 LLM 한 줄평을 그대로
띄웠는데, "관련 직책과 조직 명칭이 상위권에 고르게 배치되어" 처럼 정답의 분야를 통째로
불어버렸다. 프롬프트로 금지해도 모델이 무시한다 — 유사도 목록에 대해 할 말이 있으려면
그 목록의 성격을 말해야 하고, 그게 곧 정답의 성격이기 때문이다. 지금은 헤드라인·부제·근거
문장이 전부 숫자에서 나오는 결정론적 문자열이다. LLM 문장은 잠금 걸린 힌트 카드 안에만
들어간다. 같은 이유로 `docs/data/*.json` 의 채점 근거 문장도 base64 로 넣는다.

### 판정 표본과 힌트 표본은 다르다

판정은 **거르지 않은 원본 상위 16개**를 본다. 힌트 카드에 쓰는 유사어 목록만 정답 조각을
걷어낸 것을 쓴다. 정답이 `위원장`일 때 `부위원장·위원·상임위원장`은 뜻이 제대로 통하는
이웃이라 판정에서 빼면 문제를 실제보다 나쁘게 본다.

### 다음 보정

`docs/data/*.json` 에 `probe` · `q_reach` · `matched_ranks` · `broken` · `pos_b64` 가
매일 쌓인다. 시도 횟수는 손으로 기록해야 한다 — 그게 유일한 정답지다.

## 구조

```
komantle.py   꼬맨틀 API 클라이언트, 유사어 필터, 초성
verdict.py    판별 로직 (q_match / q_word / min / 등급 / 근거 문장)
hints.py      Gemini 호출 + 프롬프트 + 누출 가드
build.py      파이프라인 + Jinja2 렌더
templates/    index.html, archive.html
static/       style.css, app.js
docs/         빌드 산출물. Pages 아티팩트로 배포되고, 기록 누적을 위해 커밋도 된다
```

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env        # GEMINI_API_KEY 를 채운다

python build.py                              # 오늘 회차 → preview/
python build.py --out docs                   # 배포용
python build.py --puzzle-id 1611 --out preview   # 특정 회차
python build.py --no-llm --out preview           # 키 없이 (규칙 카드 4장만)
```

꼬맨틀 API는 **어제·오늘·내일 3일치만** 열어준다. 과거 회차는 조회할 수 없어서 기록은
오늘부터 하루씩 쌓인다.

`--puzzle-id` 를 주지 않으면 회차 `timestamp`를 KST로 바꿔 오늘과 맞는지 검사하고,
어긋나면 종료 코드 1로 중단한다. 어제 정답을 오늘 배포하는 사고를 막는 장치다.

## LLM이 죽어도 페이지는 나온다

Gemini 호출이 실패하면 판정은 1위 단어 점수만으로 축소하고, LLM 카드 7장은 비활성으로
렌더한다. 규칙 카드 4장(글자 수 · 유사어 ① · 유사어 ② · 초성)은 API 없이 항상 살아 있다.

## 누출 가드

LLM이 만든 모든 문자열을 검사한다.

1. 정답 문자열 포함 → 거부
2. 정답의 길이 2 이상 접두사 포함 → 거부 (`속이다` → `속이` 금지)
   접미사는 정답이 `다`로 끝나지 않을 때만 본다. `이다`까지 막으면 평범한 문장이 전부 걸린다.
3. 빈칸 예문의 `○` 개수 ≠ 정답 글자 수 → 거부

위반하면 한 번 재요청하고, 그래도 실패한 카드만 비활성으로 넘긴다.

유사어 카드는 **정답 어간과 그 종성 변이형**(`komantle.echo_terms`)을 품거나 정답에
품히는 단어를 걷어낸다.

`정답 in 단어` 만 보면 정답 `가득히`에 `한가득 · 가득가득`이, 정답 `위원장`에
`상임위원 · 위원회`가 살아남는다. 어간까지 봐도 부족하다 — 정답 `미끄럽다`의 어간
`미끄`는 `미끈`·`미끌`의 부분 문자열이 **아니다**. 종성 ㄴ·ㄹ 이 붙으면서 글자 자체가
바뀌기 때문이다. 실제로 `미끈한`(52위)이 유사어 카드에 그대로 떴다.

그래서 어간 끝 음절에 종성을 하나씩 붙인 27가지 꼴까지 같이 막는다. 종성이 이미 있는
음절은 건너뛴다(`가득`의 `득`, `위원`의 `원`). `자라` → `자랑` 처럼 남남이 걸리기도
하지만 이웃이 1000개라 한둘 빠지는 건 공짜고, 놓치면 정답이 그대로 노출된다.

LLM 프롬프트에 보여주는 금지어 목록은 읽히는 어간만 쓴다. 뜻 없는 음절 27개를
늘어놓으면 모델이 오히려 헷갈린다. 검사는 변이형까지 포함해서 한다.

## 갱신 실패는 페이지가 스스로 알린다

빌드가 실패하면 어제 페이지가 그대로 남는다. HTML 에 회차 날짜를 심어두고, 브라우저가
KST 오늘 날짜와 비교해 어긋나면 "오늘 판정이 아직 갱신되지 않았습니다" 배너를 띄운다.

- `.github/workflows/daily.yml` — cron `5 15 * * *` (UTC) = KST 00:05, `workflow_dispatch` 가능
- GitHub Pages — Settings → Pages → **Source: `GitHub Actions`**

  브랜치 기반 Pages 를 쓰면 안 된다. `GITHUB_TOKEN` 으로 만든 커밋은 다른 워크플로를
  트리거하지 않으므로([문서](https://docs.github.com/en/actions/concepts/security/github_token))
  봇이 `docs/` 를 커밋해도 Pages 빌드가 돌지 않는다. 그래서 워크플로가 `docs/` 를
  아티팩트로 올려 직접 배포한다. `docs/` 커밋은 기록(`docs/data/*.json`) 누적용으로만 남긴다.

- `GEMINI_API_KEY` — Settings → Secrets and variables → Actions 에 등록.
  **리포가 공개이므로 소스·YAML·README·커밋 메시지 어디에도 문자열로 넣지 않는다.**
  로컬은 `.env`(gitignore)를 쓴다.

카카오톡은 링크 미리보기를 캐시한다. 갱신이 필요하면 공유 URL 뒤에 `?d=회차번호`를 붙인다.

## 안 하는 것

- **카카오톡 자동 발송** — 오픈채팅방에 봇으로 메시지를 보내는 공식 API가 없다
  ([카카오 데브톡 확답](https://devtalk.kakao.com/t/api/149749)). 고정 URL 하나를 공지로 박아두는 방식이다.
- **프로브 방식 판별** — "사람이 흔히 찍는 단어가 몇 위에 걸리는가"는 도달 속도(=난이도)를
  재는 것이지 결함을 재는 게 아니다.
- **과거 회차 백필** — API가 3일치만 열어준다.
