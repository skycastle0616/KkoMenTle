# 꼬맨틀 알리미

[꼬맨틀](https://semantle-ko.newsjel.ly)은 [Semantle](https://gitlab.com/novalis_dt/semantle)의
한국어판이다. 정답과의 임베딩 유사도만으로 진행하는 구조라, 임베딩이 그 단어를 잘못 읽는 날은
문제 자체가 성립하지 않는다.

꼬맨틀은 날에 따라 문제 자체가 망가진다. 정답으로 삼기엔 무리한 단어이거나, 유사도 점수가
정답의 실제 뜻과 어긋나서 아무리 잘 추측해도 도달할 수 없는 날이 있다.

**이 페이지는 그날 문제가 풀 만한지 판별해서 크게 알려준다.** 힌트는 곁들이는 기능이다.

> 답을 찾아가는 과정이 오래 걸리는 건 난이도이고 그 자체가 게임의 재미다.
> 걸러내야 하는 건 결함이 있는 날이다.

공개 URL — <https://skycastle0616.github.io/KkoMenTle/>

## 판별 로직

축이 둘이다.

| 축 | 잡아내는 실패 | 산출 |
|---|---|---|
| `q_word` | 정답으로 내걸기에 공정하지 않은 단어 | LLM `fairness` |
| `q_match` | 유사도가 뜻을 따라가지 못하는 날 | LLM `semantic_match` + 1위 단어 점수 |

```
match_ratio = Σ(1/순위, 통하는 순위마다) / H(16)      H(16) = 3.3807
q_match     = 0.80 * match_ratio + 0.20 * norm(first_score, 38, 62)
q_word      = fairness
playable    = 100 * min(q_match, q_word)
```

**개수가 아니라 순위로 잰다.** LLM 은 개수가 아니라 통하는 단어의 **순위 번호 목록**을
돌려준다(`matched_ranks`). 1위 이웃은 16위 이웃보다 압도적으로 정보가 많다 —
`주인공` 날의 1위가 `여주인공`(58.98)이었고, 그거 하나가 사실상 답을 쥐여준다.
같은 7개라도 자리가 다르면 결과가 갈린다.

| 통하는 순위 | 개수비 | 순위가중 | 점수 |
|---|---|---|---|
| 1·2·5·6·7·14·16 | 7/16 | 0.634 | **68** 🟡 |
| 10~16 | 7/16 | 0.216 | **31** 🔴 |

`semantic_match`는 **동의어 개수가 아니라 "정답 쪽을 가리키는 단어" 개수**다. 이 게임은
유사도만 보고 답을 찾아가므로 방향만 맞으면 도달한다. 동의어만 세면 멀쩡한 날이 망가진
날로 찍힌다 — `자라다` 날에 `태어나·살아가다`를 빼고 세니 5/16 이 나와 🔴 가 떴는데,
`성장하다·키우다`가 7·8위에 있는 충분히 풀리는 날이었다. 기준을 넓혀 10/16, 🟡.

### 어간 자기반향은 한 번만 센다

정답 어간을 그대로 품은 이웃은 다 합쳐 한 개로만 센다. `가득히` 날의 상위 16에
`한가득·가득·가득가득`이 있었는데, 셋이 높게 뜨는 건 FastText가 부분 문자열을 보기
때문이지 임베딩이 뜻을 따라간다는 증거가 아니다. `semantic_match`가 재려는 건 후자다.

어간은 정답과 길이 2 이상 접두사만 본다(`hints.stem_terms`). 누출 가드가 쓰는
접미사까지 넣으면 `가득히`의 `득히`에 `그득히` 같은 남남이 걸린다. 실측: 접미사 포함
4개(오판) → 어간만 3개.

자기반향으로 걸린 순위는 **가장 높은 것 하나만 남기고** `matched_ranks` 에서 뺀다.
(`가득히`: 어간이 1·2·4위 → 1위만 남김)

`first_score`(1위 단어 점수) 비중은 0.35 였다가 0.20 으로 내렸다. 1위 점수가 낮다는 건
**점수 천장이 낮다**는 뜻이지 결함이 아니다. 목록이 제대로 가리키면 낮은 천장에서도
수렴한다. q_word 에서 걷어낸 것과 같은 혼동이 q_match 안에도 있었다. 정규화 구간도
실측 분포(39~62)에 맞춰 35~70 → 38~62 로 좁혔다.

`fairness`가 1.0 미만으로 내려가는 두 갈래를 프롬프트에 명시했다. ① 더 흔한 유의어가
대체한 경우(`네거리` ← `사거리`) ② **어근형이 파생형을 밀어냈는데 그 파생형이 정답인
경우**(`가득히` ← `가득`). ②는 목록에서 바로 보인다 — 정답의 어근형이 상위권에 독립해
앉아 있으면 그 신호다. 뜻은 같고 형태만 덜 쓰이는 것이라 0.7~0.8 정도로만 깎는다.

`q_word`는 "떠올리기 쉬운가"가 아니다. 떠올리는 데 오래 걸리는 건 난이도이고 그게 게임의
재미라서 깎을 이유가 없다. 여기서 재는 건 **그 단어를 정답으로 삼는 것 자체가 부당한가**다 —
방언, 고어·폐어, 특정 분야 전문용어, 비표준 표기. `네거리`처럼 표준어이지만 `사거리`에
거의 밀려난 말은 중간(0.6~0.8)이다.

**합산이 아니라 `min()`이다.** 예를 들어 `속이다`는 멀쩡한 표준어라 `fairness`가 1.0인데,
FastText가 이 단어를 `속(屬, 생물 분류) + 이다`로 쪼개 읽어서 유사어가 전부 생물 분류 용어다.
합산하면 `q_word`에서 점수를 그냥 먹고 등급이 올라가버린다. 둘 중 하나만 망가져도 추천하면
안 되므로 약한 고리가 점수를 결정해야 한다.

| 점수 | 배지 | 헤드라인 |
|---|---|---|
| 78+ | 🟢 | 오늘은 할 만합니다 |
| 55~77 | 🟡 | 조금 까다롭습니다 |
| 32~54 | 🟠 | 각오하고 들어가세요 |
| ~31 | 🔴 | 오늘은 건너뛰세요 |

부제는 더 약한 축을 등급까지 반영해 말한다. `match` 축은 10/16 인 날과 0/16 인 날에
같은 문장을 붙이면 🟡 이 실제보다 나쁘게 읽혀서 셋으로 나눴다.

| | 부제 |
|---|---|
| 🟢 | 유사도가 정답의 뜻을 곧게 따라가는 날입니다 |
| 🟡 `match` | 유사도가 정답의 뜻을 군데군데 놓치는 날입니다 |
| 🟠 `match` | 유사도가 정답의 뜻을 자주 놓치는 날입니다 |
| 🔴 `match` | 유사도가 정답의 뜻을 배신하는 날입니다 |
| `word` | 정답으로 내걸기엔 공정하지 않은 단어입니다 |

**판정 영역에는 LLM 자유 문장을 쓰지 않는다.** 처음엔 🟢 인 날 LLM 한 줄평을 그대로
띄웠는데, "관련 직책과 조직 명칭이 상위권에 고르게 배치되어" 처럼 정답의 분야를 통째로
불어버렸다. 프롬프트로 금지해도 모델이 무시한다 — 유사도 목록에 대해 할 말이 있으려면
그 목록의 성격을 말해야 하고, 그게 곧 정답의 성격이기 때문이다. 지금은 헤드라인·부제·근거
문장이 전부 숫자에서 나오는 결정론적 문자열이다. LLM 문장은 잠금 걸린 힌트 카드 안에만
들어간다.

같은 이유로 `docs/data/*.json` 의 채점 근거 문장도 정답과 함께 base64 로 넣는다.
공개 파일이라 평문으로 두면 그 자체가 스포일러다.

### 판정 표본과 힌트 표본은 다르다

판정은 **거르지 않은 원본 상위 16개**를 본다. 힌트 카드에 쓰는 유사어 목록만 정답 조각을
걷어낸 것을 쓴다. 정답이 `위원장`일 때 `부위원장·위원·상임위원장`은 뜻이 제대로 통하는
이웃이라 판정에서 빼면 `semantic_match`가 그만큼 깎여 문제를 실제보다 나쁘게 본다.
(실측: 거른 표본 15/16 → 원본 표본 16/16)

### 실측 검산

| 회차 | 정답 | `fairness` | `semantic_match` | 1위 점수 | 점수 | 등급 |
|---|---|---|---|---|---|---|
| 1610 | 위원장 | 1.00 | 16/16 | 61.95 | **100** | 🟢 |
| 1612 | 주문 | 1.00 | 15/16 | 52.95 | **87** | 🟢 |
| 1609 | 네거리 | 0.70 | 8/16 | 61.71 | **60** | 🟡 |
| 1613 | 자라다 | 1.00 | 10/16 | 45.92 | **57** | 🟡 |
| 1616 | 주인공 | 1.00 | 1·2·5·6·7·8·9·10·14·15·16위 | 58.98 | **78** | 🟢 |
| 1615 | 가득히 | 0.80 | 14→12/16 | 53.41 | **73** | 🟡 |
| 1611 | 속이다 | 1.00 | 없음 | 39.19 | **1** | 🔴 |

`속이다`만 🔴 로 떨어진다. 임베딩이 통째로 딴 데(생물 분류)로 튄 유일한 날이다.

`docs/data/*.json` 에는 `semantic_match`(원본) · `semantic_match_eff`(할인 후) ·
`self_echo` · `pos_b64`(품사)를 함께 남긴다. 품사는 판정에 쓰지 않는다 — "부사 날이
체계적으로 후하게 나오는가" 를 나중에 데이터로 보려고 쌓아둘 뿐이다.

### 보정을 멈추는 기간

2026-09-03 이후 **일주일간 점수식을 동결한다.** 그 전 나흘 동안 네 번 고쳤는데
(`semantic_match` 완화 → `first_score` 감량 → 자기반향 할인 → 순위 가중) 매번 근거가
그날 하루 체감 하나였다. 자기반향 할인은 다음 날 스스로 반박했다. 하루치로 규칙을
만드는 건 보정이 아니라 흔들림이다.

`matched_ranks` 가 매일 쌓이므로 다음 보정은 하루 체감이 아니라 일주일치로 한다.

## 구조

```
komantle.py   꼬맨틀 API 클라이언트, 유사어 필터, 초성
verdict.py    판별 로직 (q_match / q_word / min / 등급 / 근거 문장)
hints.py      Gemini 호출 + 프롬프트 + 누출 가드
build.py      파이프라인 + Jinja2 렌더
templates/    index.html, archive.html
static/       style.css, app.js
docs/         빌드 산출물. Pages 아티팩트로 배포되고, 기록 누적을 위해 커밋도 된다
```

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env        # GEMINI_API_KEY 를 채운다

python build.py                              # 오늘 회차 → preview/
python build.py --out docs                   # 배포용
python build.py --puzzle-id 1611 --out preview   # 특정 회차
python build.py --no-llm --out preview           # 키 없이 (규칙 카드 4장만)
```

꼬맨틀 API는 **어제·오늘·내일 3일치만** 열어준다. 과거 회차는 조회할 수 없어서 기록은
오늘부터 하루씩 쌓인다.

`--puzzle-id` 를 주지 않으면 회차 `timestamp`를 KST로 바꿔 오늘과 맞는지 검사하고,
어긋나면 종료 코드 1로 중단한다. 어제 정답을 오늘 배포하는 사고를 막는 장치다.

## LLM이 죽어도 페이지는 나온다

Gemini 호출이 실패하면 판정은 1위 단어 점수만으로 축소하고, LLM 카드 7장은 비활성으로
렌더한다. 규칙 카드 4장(글자 수 · 유사어 ① · 유사어 ② · 초성)은 API 없이 항상 살아 있다.

## 누출 가드

LLM이 만든 모든 문자열을 검사한다.

1. 정답 문자열 포함 → 거부
2. 정답의 길이 2 이상 접두사 포함 → 거부 (`속이다` → `속이` 금지)
   접미사는 정답이 `다`로 끝나지 않을 때만 본다. `이다`까지 막으면 평범한 문장이 전부 걸린다.
3. 빈칸 예문의 `○` 개수 ≠ 정답 글자 수 → 거부

위반하면 한 번 재요청하고, 그래도 실패한 카드만 비활성으로 넘긴다.

유사어 카드는 **정답 어간과 그 종성 변이형**(`komantle.echo_terms`)을 품거나 정답에
품히는 단어를 걷어낸다.

`정답 in 단어` 만 보면 정답 `가득히`에 `한가득 · 가득가득`이, 정답 `위원장`에
`상임위원 · 위원회`가 살아남는다. 어간까지 봐도 부족하다 — 정답 `미끄럽다`의 어간
`미끄`는 `미끈`·`미끌`의 부분 문자열이 **아니다**. 종성 ㄴ·ㄹ 이 붙으면서 글자 자체가
바뀌기 때문이다. 실제로 `미끈한`(52위)이 유사어 카드에 그대로 떴다.

그래서 어간 끝 음절에 종성을 하나씩 붙인 27가지 꼴까지 같이 막는다. 종성이 이미 있는
음절은 건너뛴다(`가득`의 `득`, `위원`의 `원`). `자라` → `자랑` 처럼 남남이 걸리기도
하지만 이웃이 1000개라 한둘 빠지는 건 공짜고, 놓치면 정답이 그대로 노출된다.

LLM 프롬프트에 보여주는 금지어 목록은 읽히는 어간만 쓴다. 뜻 없는 음절 27개를
늘어놓으면 모델이 오히려 헷갈린다. 검사는 변이형까지 포함해서 한다.

## 갱신 실패는 페이지가 스스로 알린다

빌드가 실패하면 어제 페이지가 그대로 남는다. HTML 에 회차 날짜를 심어두고, 브라우저가
KST 오늘 날짜와 비교해 어긋나면 "오늘 판정이 아직 갱신되지 않았습니다" 배너를 띄운다.

## 배포

- `.github/workflows/daily.yml` — cron `5 15 * * *` (UTC) = KST 00:05, `workflow_dispatch` 가능
- GitHub Pages — Settings → Pages → **Source: `GitHub Actions`**

  브랜치 기반 Pages 를 쓰면 안 된다. `GITHUB_TOKEN` 으로 만든 커밋은 다른 워크플로를
  트리거하지 않으므로([문서](https://docs.github.com/en/actions/concepts/security/github_token))
  봇이 `docs/` 를 커밋해도 Pages 빌드가 돌지 않는다. 그래서 워크플로가 `docs/` 를
  아티팩트로 올려 직접 배포한다. `docs/` 커밋은 기록(`docs/data/*.json`) 누적용으로만 남긴다.

- `GEMINI_API_KEY` — Settings → Secrets and variables → Actions 에 등록.
  **리포가 공개이므로 소스·YAML·README·커밋 메시지 어디에도 문자열로 넣지 않는다.**
  로컬은 `.env`(gitignore)를 쓴다.

카카오톡은 링크 미리보기를 캐시한다. 갱신이 필요하면 공유 URL 뒤에 `?d=회차번호`를 붙인다.

## 안 하는 것

- **카카오톡 자동 발송** — 오픈채팅방에 봇으로 메시지를 보내는 공식 API가 없다
  ([카카오 데브톡 확답](https://devtalk.kakao.com/t/api/149749)). 고정 URL 하나를 공지로 박아두는 방식이다.
- **프로브 방식 판별** — "사람이 흔히 찍는 단어가 몇 위에 걸리는가"는 도달 속도(=난이도)를
  재는 것이지 결함을 재는 게 아니다.
- **과거 회차 백필** — API가 3일치만 열어준다.
